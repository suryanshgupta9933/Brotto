# Decision: First vertical candidate — Defer to data

**Date:** 2026-09-28
**Question:** Q7 (open-questions.md)
**Status:** Accepted (placeholder)

## Context

Top vertical candidates from the pain-points research: recruiters, e-commerce operators, real estate agents, QA / test automation, customer-ops. Combined with C1 (generalist first 6 months) and Q5 (spinout trigger = 10 enterprise customers in same vertical), the natural conclusion is: don't commit to candidates ahead of usage data.

## Choice

**Defer entirely. Revisit at the same time as Q5 (when spinout trigger fires).**

No vertical preferences are pre-locked. The data picks.

## Consequences

**Enabled:**
- Zero pre-commitment bias
- Vertical emerges from real usage, not from assumptions
- Marketing stays generalist until vertical signal exists

**Closed off:**
- No vertical-shaped features in Phase 1–4 (don't accidentally build recruiter-shaped UX that locks you out of other verticals)

**New constraints:**
- Skill library metadata must support vertical tagging (already planned for Hybrid marketplace)
- Task history metadata must capture enough domain/action/workflow shape to enable vertical analysis later
