# Governance

## Project Governance

The Brotto Browser Automation Platform is an open-source project governed by the principles defined in this document.

## Project Leadership

### Maintainers

The project is maintained by the Inventic engineering team. Maintainers are responsible for:

- Reviewing and merging pull requests
- Managing releases and versioning
- Setting technical direction
- Resolving disputes and enforcing code of conduct

### Technical Steering

Major architectural decisions are made through Architecture Decision Records (ADRs) located in `docs/adrs/`. The ADR process allows for:

- Transparent decision making
- Historical context for design choices
- Community input on significant changes

## Contribution Process

1. Fork the repository
2. Create a feature branch
3. Make changes with tests
4. Submit a pull request with ADR if applicable
5. Maintainers review and approve

## Decision Making

- **Minor changes**: Maintainer approval
- **Moderate changes**: Two maintainer approvals
- **Major/breaking changes**: Requires ADR + community feedback period

## Release Process

1. Version bumps follow Semantic Versioning
2. Releases are tagged with Git tags
3. Release notes are generated from conventional commits
4. Security releases are expedited as needed

## Conflict Resolution

Disagreements are resolved through:

1. Discussion and consensus building
2. Technical merit arguments
3.最终 decision by lead maintainer

## Communication

- GitHub Issues: Feature requests and bug reports
- GitHub Discussions: Q&A and design discussions
- Security issues: security@inventic.io

## Update History

This governance document will be updated as the project evolves.
